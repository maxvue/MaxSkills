## Goal
Establish standard patterns and rules for managing, debugging, and implementing the editorial calendar event lifecycle, its state transitions, and the asynchronous AI-agent orquestration jobs using AdonisJS v6 and BullMQ.

## Instructions

### 1. Editorial Calendar Event Status Lifecycle
Ensure that all database queries, state transitions, and business logic respect the following canonical states of a `CalendarEvent`:
* **`planned`**: Initial state generated by the strategic `StrategyManagerJob` containing only base ideas and instructions.
* **`planning_approved`**: Triggered when the user approves the planning phase. This state automatically dispatches the `CopywriterJob`.
* **`script_drafted`**: Set when the `CopywriterJob` finishes generating the initial post copy and slide briefs using the `SaveDraftScript` tool.
* **`script_ready`**: Set when the `CopywriterReviewerJob` reviews, adjusts, and approves the script using the `SaveEventScript` tool.
* **`art_ready`**: Set automatically by `GenerateEventArtwork` tool inside `GraphicEditorJob` once all slides of the script have a generated artwork (path exists).
* **`art_analysing`**: Set if the user continues the event workflow but there are rejected slides. It dispatches the `ArtAnalystJob` to synthesize feedback.
* **`art_rejected`**: Set by the `SaveArtAnalysis` tool at the end of the `ArtAnalystJob`, moving the event back to the copywriter phase for revision.
* **`replanning`**: Set when a complete regeneration is triggered (e.g., due to repeated art failures or manual restart). Dispatches `ReplanEventJob` and returns to `planned` upon completion.
* **`scheduled`**: Set when the user approves all slides in `art_ready`, scheduling the post for automatic publication at `startAt`.
* **`published`**: Set when the `PublishEventJob` successfully posts the content on Meta platforms (Instagram/Facebook).
* **`failed`**: Set when publication fails, storing the error message in the `publishError` column.

### 2. State Transition Tools
Verify and implement the correct tools for state changes in controllers or AI jobs:
* **`SaveDraftScript`**: Integrates in `CopywriterJob`. Must receive `event_id` and the markdown copy. Transitions event status to `script_drafted`.
* **`SaveEventScript`**: Integrates in `CopywriterReviewerJob`. Must receive `event_id` and the final copy. Transitions event status to `script_ready` and clears `rejectionObservations`.
* **`GenerateEventArtwork`**: Integrates in `GraphicEditorJob`. Generates and saves images individually per slide. Automatically transitions event status to `art_ready` when `generated_slides >= total_slides`.
* **`SaveArtAnalysis`**: Integrates in `ArtAnalystJob`. Registers approved and rejected visual elements, then transitions event status to `art_rejected`.
* **`UpdateCalendarItem`**: Integrates in `ReplanEventJob`. Updates base themes and instructions, returning status to `planned`.

### 3. Review Mode (Partial Regeneration)
When handling an event with status `art_rejected` or transitioning from it:
* **Copywriter Agent**: Must enter "Revision Mode". It must read previous reviews via `GetCalendarEventData`, and revise **ONLY** the slides marked with `status = 'rejected'` in `CalendarEventArtwork`. Slides marked as `approved` must be left untouched.
* **Copywriter Reviewer Agent**: In partial revision, it must verify and refine **ONLY** the modified rejected slides.
* **Graphic Editor Agent**: Must generate new artwork **ONLY** for slides with `status = 'rejected'`. It must skip generating artwork for slides with `status = 'approved'` to avoid duplication of image generation costs.

### 4. BullMQ Queues and Jobs Orchestration
Validate that workers listen to their respective queues and behave deterministically according to the event status:
* **`strategy-manager`**: Handles calendar initial items setup.
* **`copywriter`**: Processes `planning_approved` (new creation) or `art_rejected` (partial revision).
* **`copywriter-reviewer`**: Processes `script_drafted`.
* **`graphic-editor`**: Processes `script_ready` (generates new artwork for pending/rejected slides).
* **`art-analyst`**: Processes `art_analysing` to compile rejection feedback.
* **`replan-event`**: Processes `replanning` status to update post baseline parameters.
* **`publish-event`**: Sends final assets and texts to Meta Graph APIs.

## Constraints
* **DO NOT** trigger `CopywriterJob` manually if the status is already `script_drafted` or `script_ready` unless explicitly requested or transitioning back from `art_rejected`.
* **DO NOT** regenerate artwork for slides that are already marked as `approved` in `CalendarEventArtwork` database table.
* **DO NOT** allow status transitions that bypass the sequence (e.g., transitioning directly from `planned` to `script_ready`).
* **DO NOT** write raw SQL queries for event status updates; always use Lucid ORM model hooks and events for proper integration.
* **NEVER** edit the post title or script if the event status is `scheduled` or `published`.
